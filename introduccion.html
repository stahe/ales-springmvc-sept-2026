Sin embargo, esto no es necesario: este documento se basta a sí mismo y no supone ningún conocimiento previo de [ASP.NET] ni, por lo demás, de [Spring]. Los únicos requisitos previos son una comprensión básica de la programación web (el protocolo HTTP, el lenguaje HTML) y del lenguaje [Java].

    1.1. El papel de Spring MVC en una aplicación web

    Una aplicación web suele construirse en capas, y cada capa se comunica solo con las capas vecinas:

    • la capa web recibe las solicitudes HTTP del navegador y le devuelve páginas HTML. [Spring MVC] nos ayuda a escribir esta capa;
    • la capa de negocio contiene las reglas de negocio de la aplicación (por ejemplo, “un paciente solo puede tener una cita próxima”). No sabe nada de la web: podría servir igualmente a una aplicación de línea de comandos;
    • la capa de acceso a datos (capa [DAO], por [Data Access Object]) lee y escribe en la base de datos. Usaremos [Spring Data JPA], que se apoya en el ORM [Hibernate] ([Object Relational Mapper]) para mapear las filas de las tablas y los objetos en [Java].

    La propia capa web sigue el modelo [MVC] ([Model – View – Controller]):

    • el controlador (C) es una clase cuyos métodos, llamados acciones, atienden cada uno un tipo específico de solicitud (por ejemplo, [GET /schedule]). Una acción lee los parámetros de la solicitud, invoca la capa de negocio y luego selecciona la vista que se mostrará;
    • el modelo (M) es el conjunto de datos que la acción pasa a la vista;
    • la vista (V) es un archivo [Thymeleaf] (con la extensión [.html]): una página HTML en la que ciertas etiquetas tienen atributos [th:...] ([th:text], [th:each]...), que el motor [Thymeleaf] reemplaza con datos del modelo.

    El procesamiento de una solicitud sigue los pasos numerados del diagrama:

    • 1: El navegador envía una solicitud HTTP, por ejemplo, [GET /schedule?doctorId=1&day=2026-09-24];
    • 2: El servidor web [Tomcat], integrado en la aplicación por [Spring Boot], recibe la solicitud. Esta pasa por una serie de filtros (lectura de cookies, autenticación, etc.) y luego llega a [DispatcherServlet], el único punto de entrada de [Spring MVC], que selecciona la acción responsable de atender esta solicitud: es el enrutamiento. Antes de llegar a la acción, la solicitud todavía puede pasar por interceptores, que exploraremos en capítulos posteriores;
    • 3: La acción solicita a la capa de negocio los datos que necesita; si es necesario, la capa de negocio recurre a la capa [DAO], que consulta la base de datos [MySQL] en SQL;
    • 4: La acción construye el modelo de vista M y designa la vista que debe mostrarlo;
    • 5: El motor de vistas [Thymeleaf] genera el HTML de la página, que [Spring MVC] devuelve al navegador.

    [Spring] es el framework más utilizado del mundo ([Java]) para desarrollar aplicaciones empresariales. Gratuito y de código abierto, funciona en cualquier lugar donde funcione [Java] ([Windows], [Linux], [macOS]). [Spring MVC] es el componente web; [Spring Boot] es una capa superior que configura automáticamente todo el conjunto (servidor web, conversión JSON, motor de vistas, acceso a datos, etc.) según las bibliotecas presentes en el proyecto, y convierte la aplicación en un programa [Java] estándar, lanzado por un método [main]. [Spring MVC] puede crear servidores que devuelven JSON a un cliente [JavaScript] ([Angular], [React], [Flutter]...) así como aplicaciones web tradicionales, en las que el servidor genera las páginas HTML y el navegador simplemente las muestra. Este documento se centra en este último caso de uso. Al igual que [ASP.NET Core], [Spring] se basa en dos ideas: las anotaciones ([@GetMapping], [@RequestMapping], [@PreAuthorize]...) describen los roles de las clases y los métodos, y la inyección de dependencias proporciona a cada objeto las dependencias que necesita. [Spring] es, de hecho, uno de los frameworks que popularizaron esta segunda idea.

    1.2. Herramientas utilizadas

    Los ejemplos se escribieron y probaron con las siguientes herramientas (su instalación se describe en el apéndice):

    • [JDK] 21 ([Java Development Kit]), que contiene el compilador [javac] y la máquina virtual [java]. [Java] 21 es una versión LTS (soporte a largo plazo);
    • la herramienta de compilación [Maven] 3.9.11, que no necesita instalarse: cada proyecto contiene un Maven Wrapper (los scripts [mvnw] y [mvnw.cmd]), que descarga automáticamente la versión correcta de [Maven] en el primer uso;
    • el editor [Visual Studio Code], junto con las extensiones [Extension Pack for Java] y [Spring Boot Extension Pack] ;
    • un navegador reciente ([Chrome], [Firefox], [Edge]);
    • la herramienta de línea de comandos [curl], que muestra las respuestas HTTP sin procesar (viene incluida en [Windows] 10 y 11);
    • el SGBD [MySQL] (o [MariaDB]), por ejemplo, el de [Laragon] en [Windows], a partir del capítulo sobre acceso a datos y para el caso de estudio.

    A diferencia del SDK y de [.NET], que contienen [ASP.NET Core], [JDK] no contiene [Spring]: el framework es un conjunto de bibliotecas que [Maven] descarga del repositorio central [Maven Central] durante la primera compilación (por lo que debe estar conectado a Internet ese día) y luego almacena en una carpeta local ([.m2] en el directorio personal del usuario). Estas bibliotecas se agrupan en starters: un starter es una única dependencia que aporta todo lo necesario para una funcionalidad específica. Todos los ejemplos usan [spring-boot-starter-webmvc] ([Spring MVC] y el servidor [Tomcat]); además, están [spring-boot-starter-validation] (validación de datos, a partir del capítulo 3), [spring-boot-starter-thymeleaf] (vistas, a partir del capítulo 4), [spring-boot-starter-security-oauth2-resource-server] ([Spring Security] y los tokens JWT, en el capítulo 8), [spring-boot-starter-data-jpa] y el controlador [mysql-connector-j] (acceso a la base de datos, en el capítulo 9). Las versiones utilizadas son las de [Spring Boot] 4.1.1: [Spring Framework] 7.0.9, [Spring Security] 7.1.1, [Hibernate] 7.4.5, [Thymeleaf] 3.1.5, [Jackson] 3 (conversión desde JSON) y [Tomcat] 11.

    1.3. Ejecutar el caso de estudio

    Nota del revisor: aconsejo al lector que complete de inmediato el caso de estudio como se describe a continuación. Una vez que comprenda bien el papel de esta aplicación de agenda de citas, pida a su IA favorita que modifique la aplicación de la siguiente manera: a partir de ahora, cada médico podrá:

    • definir sus propios horarios de cita entre dos fechas. Esto le permitirá ajustar su agenda según sea necesario;
    • quitar ciertos horarios del calendario para un día determinado, por ejemplo, si no está disponible por motivos personales;

    La modificación no es trivial porque implica un cambio en la estructura de la base de datos. Pida a la IA que le proporcione el nuevo código de la aplicación y el script SQL para crear la nueva base de datos. Para ello, deberá proporcionarle el archivo ZIP con el proyecto completo, así como el script SQL de la base de datos anterior.

    Además, no he revisado el curso creado por Claude. Él ya había producido dos cursos perfectos: [NestJS] y [ASP.NET Core MVC]. Supuse que lo mismo ocurriría con este. Si tiene problemas para entender algo, la solución es siempre la misma: pida a su IA favorita que le explique lo que no entiende. Claude, por ejemplo, es muy bueno para esto. Puede que necesite “subirle” el ejemplo que no entiende.

    • Líneas 14–19: el proyecto padre hereda a su vez de un padre, [spring-boot-starter-parent], versión 4.1.1. Este proyecto fija las versiones de todas las bibliotecas de [Spring] y de las bibliotecas que estas usan, elegidas para funcionar juntas: por eso ninguna dependencia especifica una versión más adelante. También controla la compilación (codificación UTF-8 del código fuente, versión de [Java]...). El elemento vacío [<relativePath/>] indica que este padre no está en una carpeta vecina, sino que debe buscarse en los repositorios de [Maven];
    • líneas 22–24: la identidad del proyecto: un grupo ([groupId]), un nombre ([artifactId]) y una versión. Los módulos usan esta identidad para referirse a su padre;
    • línea 26: un proyecto de tipo [pom] no produce clases ni archivos empaquetados; agrupa módulos y les transmite su configuración;
    • líneas 28–31: la versión de destino de [Java]: [Java] 21;
    • líneas 34–63: los módulos, uno por uno; por ejemplo, el nombre de su carpeta. Un comando de [Maven] ejecutado en la carpeta [examples] se aplica a todos los módulos;
    • líneas 66–78: dependencias comunes a todos los ejemplos, heredadas por cada módulo;
    • líneas 68–71: el starter [spring-boot-starter-webmvc] aporta [Spring MVC], el servidor web [Tomcat] integrado en la aplicación (no es necesario instalar ningún servidor) y la biblioteca [Jackson], que convierte objetos [Java] a JSON;
    • Líneas 73–77: [Spring Boot DevTools], herramientas de desarrollo: reinicio automático de la aplicación cuando se recompila una clase, desactivación de cachés (como la caché de vistas) y mensajes de error más detallados. Son solo para desarrollo: el plugin de [Spring Boot] (líneas 80–88) no las incluye en el archivo ejecutable ([.jar]) destinado a producción, y se desactivan automáticamente si la aplicación se inicia con [java -jar];
    • líneas 80–88: el plugin de [Maven] para [Spring Boot]. Este plugin proporciona el comando [spring-boot:run], así como la creación de un archivo ejecutable ([mvnw package]).
