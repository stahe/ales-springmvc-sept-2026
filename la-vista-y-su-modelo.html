    4. La vista y su modelo

    Hasta este punto, las acciones han generado sus propias respuestas: texto, JSON y algunas etiquetas HTML escritas como una cadena. En una aplicación MVC, este es el papel de una vista: un archivo que describe la página HTML, con marcadores de posición para los datos que le pasa la acción: el modelo de la vista. [Spring MVC] no proporciona por sí mismo un lenguaje de vistas: puede trabajar con varios motores de vistas ([Thymeleaf], [FreeMarker], [Mustache], [JSP]...). Este curso utiliza [Thymeleaf], el motor de vistas más utilizado junto con [Spring MVC], que [Spring Boot] puede configurar por sí solo.

    Una vista [Thymeleaf] es un archivo [.html] estándar: un archivo HTML válido que puede abrirse tal cual en un navegador. Los datos se insertan en él mediante atributos adicionales con el prefijo [th:] ([th:text], [th:if], [th:each]...), que [Thymeleaf] ejecuta en el servidor y luego elimina de la página. A esto es a lo que [Thymeleaf] llama plantillas naturales ([natural templates]): un diseñador gráfico puede trabajar en la vista sin iniciar la aplicación, y el desarrollador le agrega los atributos [th:]. Esto difiere de [Razor], el motor de vistas de [ASP.NET Core MVC], que combina HTML y código [C#] precedido por el carácter [@].

    package example13.controllers;

import java.time.LocalTime;
import java.time.format.DateTimeFormatter;
import java.util.Map;

import org.springframework.http.HttpStatus;
import org.springframework.stereotype.Controller;
import org.springframework.ui.Model;
import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.servlet.ModelAndView;

import example13.models.PageModel;

// @Controller: las acciones devuelven el NOMBRE de una vista
@Controller
public class ViewsController {

    private static final DateTimeFormatter TIME = DateTimeFormatter.ofPattern("HH:mm:ss");

    // Model: el modelo de la vista, un diccionario llenado por la acción;
    // la cadena devuelta es el nombre de la vista: templates/views/index.html
    @GetMapping("/")
    public String index(Model model) {
        PageModel pageModel = new PageModel(
                "My first view",
                "This page was built by Thymeleaf, on the server.",
                LocalTime.now().format(TIME));
        model.addAttribute("model", pageModel);
        return "views/index";
    }

    // ModelAndView: la vista, su modelo y, si es necesario, el código de respuesta, en un solo objeto
    @GetMapping("/hello/{name}")
    public ModelAndView hello(@PathVariable String name) {
        if (name.equals("unknown")) {
            return new ModelAndView("views/unknown", Map.of("name", name), HttpStatus.NOT_FOUND);
        }
        PageModel pageModel = new PageModel(
                "Hello " + name,
                "This time, the action built a ModelAndView object.",
                LocalTime.now().format(TIME));
        return new ModelAndView("views/index", Map.of("model", pageModel));
    }
}

    Comentemos este código:

    • Línea 17: la anotación [@Controller] reemplaza a la anotación [@RestController] de los ejemplos anteriores. Con [@RestController], lo que devuelve una acción es la respuesta (texto, JSON). Con [@Controller], una acción que devuelve una cadena devuelve el nombre de una vista: es la vista la que generará la respuesta;
    • línea 25: la acción recibe un parámetro de tipo [Model], proporcionado por [Spring MVC]. Este es el modelo de la vista: un diccionario, donde cada entrada (un atributo) asocia un nombre con un objeto;
    • Líneas 26-30: la acción crea un objeto [PageModel] (un título, un mensaje, la hora actual) y lo almacena en el modelo con el nombre [model]. La vista lo recuperará con este nombre;
    • línea 31: la acción devuelve el nombre de la vista, [views/index]. Ya no crea la respuesta; en su lugar, hace referencia a una vista y ha preparado sus datos;
    • línea 36: la acción [hello] devuelve un objeto [ModelAndView], que combina el nombre de la vista y su modelo en un solo objeto. Esta es otra forma de escribir una acción que utiliza una vista;
    • Línea 38: cuando la vista depende de la solicitud, la acción selecciona la vista. Aquí, el nombre [unknown] muestra la vista [views/unknown], con código de estado 404: el tercer argumento del constructor de [ModelAndView] es el código de respuesta. El modelo de esta vista contiene una cadena simple: el nombre solicitado. [Map.of(...)] crea un diccionario de solo lectura;
    • línea 44: las dos acciones comparten la misma vista, [views/index], con modelos distintos.

    ¿Dónde busca [Spring MVC] la vista [views/index]? Pasa el nombre de la vista a un resolutor de vistas ([ViewResolver]), que lo convierte en una vista concreta. El que configura [Spring Boot] para [Thymeleaf] ([ThymeleafViewResolver]) agrega un prefijo, [classpath:/templates/], y un sufijo, [.html]: la vista [views/index] es el archivo [templates/views/index.html] del classpath, es decir, las carpetas y los archivos comprimidos donde la máquina virtual [Java] busca las clases y los recursos de la aplicación. La carpeta [src/main/resources] del proyecto forma parte de él: [Maven] copia su contenido en [target/classes], junto a las clases compiladas. Estos dos valores pueden modificarse en [application.properties] (propiedades [spring.thymeleaf.prefix] y [spring.thymeleaf.suffix]). A diferencia de [ASP.NET Core MVC], no existe una convención que derive el nombre de la vista a partir de los nombres del controlador y de la acción: la acción siempre especifica la ruta de la vista, relativa a la carpeta [templates].     Comentemos este código:

    • Línea 2: un comentario de [Thymeleaf] se escribe como [<!--/* ... */-->]. Es un comentario HTML cuyo contenido está delimitado por [/*] y [*/]: [Thymeleaf] lo elimina de la página generada, mientras que un comentario HTML normal ([<!-- -->]) se enviaría al navegador;
    • Línea 3: el atributo [xmlns:th] declara el espacio de nombres de los atributos [th:]. Está destinado únicamente a los editores de código (autocompletado, validación): [Thymeleaf] procesa los atributos [th:] incluso sin él, y lo elimina de la página generada;
    • Línea 6: el atributo [th:text] reemplaza el contenido de la etiqueta por el valor de la expresión. [${model.title}] es una expresión de variable: [model] es el atributo del modelo establecido por la acción, y [.title] llama a su accesor, [title()]. El texto "Page Title" escrito dentro de la etiqueta es solo un ejemplo, que se muestra cuando el archivo se abre directamente en un navegador; desaparece de la página generada;
    • líneas 9-11: el mismo principio se aplica al título, al mensaje y a la hora. Para insertar un valor en medio de un texto, envuélvalo en una etiqueta [<span>], que lleva el atributo [th:text].

    [${...}] las expresiones se escriben en el lenguaje de expresiones de [Spring], [SpEL] ([Spring Expression Language]). [model.title] llama al método [getTitle()] de un [JavaBean], o al método [title()] de un record: en ambos casos se escribe el mismo código.

    Una vista [Thymeleaf] no se compila con la aplicación: se lee y se interpreta cuando se solicita la página. Por lo tanto, un error en una vista no se informa en tiempo de compilación, sino cuando se muestra la página. Si se escribe [${model.titl}] en la vista, la solicitud falla (código de estado 500) y la consola del servidor muestra: [Property or field 'titl' cannot be found on object of type 'example13.models.PageModel']. De manera similar, un nombre de vista que no corresponde a ningún archivo provoca el error [Error resolving template [views/missing], template might not exist or might not be accessible by any of the configured Template Resolvers].   <p>5. Your cart:
    <th:block th:if="${#lists.isEmpty(model.cart)}">it is empty.</th:block>

  </p>

    Comentemos este código:

    • Línea 8: el atributo [th:with] declara variables locales que pueden utilizarse dentro de la etiqueta que lo contiene y en todas sus etiquetas hijas (en este caso, [total] y [count]) en todo el cuerpo de la página. [model.products.![price]] es una proyección de [SpEL]: la lista de precios de los productos. [#aggregates] y [#lists] son objetos de utilidad de [Thymeleaf] (comienzan con [#]): [#aggregates.sum] calcula la suma de una lista de números; [#lists.size] cuenta los elementos de una lista;
    • líneas 10-11: un comentario [Thymeleaf], que está ausente de la página generada;
    • línea 12: un valor [null] ([${model.nickname}]) no muestra nada, sin error;
    • líneas 14-15: [th:text] escapa los caracteres especiales de HTML ([<] se convierte en [&lt;]...): el texto se muestra tal cual. [th:utext] ([unescaped text]) lo inserta sin escapar: se interpreta como HTML. [th:utext] solo se utiliza para HTML generado por la aplicación, nunca para datos ingresados por un usuario: el usuario podría inyectar HTML, o incluso [JavaScript], en la página (un ataque conocido como [XSS], [cross-site scripting]);
    • Líneas 17-18: una condición. [th:if] conserva la etiqueta (y su contenido) si la expresión es verdadera, y la elimina en caso contrario; [th:unless] hace lo contrario. No existe [th:else]: se escribe la condición opuesta;
    • Línea 22: un bucle. El atributo [th:each] repite la etiqueta que lo contiene (en este caso, [<li>]) una vez por cada elemento de la lista. [product] es el elemento actual; [stat], que es opcional, es el estado de la iteración: [stat.index] (comienza en 0), [stat.count] (comienza en 1), [stat.size], [stat.first], [stat.last], [stat.even], [stat.odd]. En el texto de la etiqueta, [[[${product.name}]]] es una expresión en línea: inserta el valor, escapado como en [th:text], sin la etiqueta [<span>] (la forma [[(...)]] inserta sin escapar, como [th:utext]);
    • línea 23: el operador condicional [condition ? value1 : value2]. Las cadenas literales se escriben entre comillas simples;
    • líneas 24-25: [th:block] es una etiqueta específica de [Thymeleaf]: sirve únicamente para portar los atributos [th:] y desaparece de la página generada, dejando solo su contenido. [stat.first] y [stat.last] verifican la posición dentro del bucle;

import java.math.BigDecimal;

import org.springframework.context.i18n.LocaleContextHolder;
import org.springframework.stereotype.Component;

// @Component("formats"): un bean llamado [formats], que las vistas invocan
// con ${@formats.money(...)}
@Component("formats")
public class Formats {

    // "keyboard" -> "KEYBOARD"; Locale.ROOT: el resultado no depende del idioma
    public String uppercase(String text) {
        return text == null ? "" : text.toUpperCase(Locale.ROOT);
    }

    // un monto en una moneda, en el formato del idioma de la solicitud
    public String money(BigDecimal amount, String currency) {
        // el idioma de la solicitud actual, establecido por el LocaleResolver (vea WebConfig)
        Locale language = LocaleContextHolder.getLocale();
        NumberFormat format = NumberFormat.getCurrencyInstance(language);
        format.setCurrency(Currency.getInstance(currency));
        return format.format(amount);
    }

    // lo mismo, en euros
    public String money(BigDecimal amount) {
        return money(amount, "EUR");
    }

    // una fecha en palabras completas, en el idioma de la solicitud: "Friday, September 25, 2026"
    public String date(LocalDate day) {
        return day.format(DateTimeFormatter.ofLocalizedDate(FormatStyle.FULL).withLocale(LocaleContextHolder.getLocale()));
    }
}

import org.thymeleaf.context.ITemplateContext;
import org.thymeleaf.context.IWebContext;
import org.thymeleaf.engine.AttributeName;
import org.thymeleaf.model.IProcessableElementTag;

// el procesador del atributo ex:active: <a href="/products" ex:active="/products">
// recibe la clase "active" si la página actual está bajo esta ruta
public class ActiveProcessor extends AbstractAttributeTagProcessor {

    public ActiveProcessor(String prefix) {
        // HTML; solo etiquetas <a>; atributo [ex:active]; precedencia; true: el
        // atributo ex:active se elimina de la página producida
        super(TemplateMode.HTML, prefix, "a", false, "active", true, 1000, true);
    }

    // se invoca por cada etiqueta <a> que lleva el atributo ex:active
    @Override
    protected void doProcess(ITemplateContext context, IProcessableElementTag tag,
            AttributeName attributeName, String value, IElementTagStructureHandler structure) {
        // la ruta de la página, leída de la solicitud actual
        String path = context instanceof IWebContext web ? web.getExchange().getRequest().getRequestPath() : "";
        boolean isActive = value.equals("/") ? path.equals("/") : path.startsWith(value);
        if (isActive) {
            // agregamos la clase "active" al atributo class de la etiqueta
            String classes = tag.getAttributeValue("class");
            structure.setAttribute("class", classes == null ? "active" : classes + " active");
        }
    }
}

            new Book("Le Rouge et le Noir", "Stendhal", "novel"),
            new Book("Les Fleurs du mal", "Baudelaire", "poetry"),
            new Book("Madame Bovary", "Flaubert", "novel"),
            new Book("Alcools", "Apollinaire", "poetry"),
            new Book("Le Cid", "Corneille", "drama"));

    // GET / y GET /search?keyword=...&genre=...: el formulario Y sus resultados
    @GetMapping({ "/", "/search" })
    public String search(@RequestParam(required = false) String keyword,
            @RequestParam(required = false) String genre, Model model) {
        String word = keyword == null ? "" : keyword.trim().toLowerCase(Locale.ROOT);
        List<Book> results = BOOKS.stream()
                .filter(b -> word.isEmpty() || b.title().toLowerCase(Locale.ROOT).contains(word)
                        || b.author().toLowerCase(Locale.ROOT).contains(word))
                .filter(b -> genre == null || genre.isEmpty() || b.genre().equals(genre))
                .toList();
        model.addAttribute("model", new SearchModel(keyword == null ? "" : keyword,
                genre == null ? "" : genre, GENRES, results));
        return "books/search";
    }
}

import java.util.Objects;

import jakarta.validation.constraints.AssertTrue;
import jakarta.validation.constraints.Email;
import jakarta.validation.constraints.Max;
import jakarta.validation.constraints.Min;
import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.NotNull;
import jakarta.validation.constraints.Size;

// los campos del formulario y sus restricciones
public class RegistrationModel {

    @NotBlank(message = "The name is required.")
    @Size(max = 20, message = "The name must not exceed 20 characters.")
    private String name;

    @NotBlank(message = "The email address is required.")
    @Email(message = "Invalid email address.")
    private String email;

    // todo lo que viene de un formulario es una cadena: "42" -> 42
    @NotNull(message = "The age is required.")
    @Min(value = 18, message = "The age must be between 18 and 120 years.")
    @Max(value = 120, message = "The age must be between 18 and 120 years.")
    private Integer age;

    @NotBlank(message = "The password is required.")
    @Size(min = 6, message = "The password must have at least 6 characters.")
    private String password;

    private String confirmation;

    // una regla sobre DOS campos: un método booleano, validado por
    // @AssertTrue. Para Bean Validation, es la propiedad [confirmationValid].
    @AssertTrue(message = "The confirmation does not match the password.")
    public boolean isConfirmationValid() {
        return Objects.equals(password, confirmation);
    }

    public String getName() { return name; }
    public void setName(String name) { this.name = name; }

    public String getEmail() { return email; }
    public void setEmail(String email) { this.email = email; }

    public Integer getAge() { return age; }
    public void setAge(Integer age) { this.age = age; }

    public String getPassword() { return password; }
    public void setPassword(String password) { this.password = password; }

    public String getConfirmation() { return confirmation; }
    public void setConfirmation(String confirmation) { this.confirmation = confirmation; }
}

@Controller
@RequestMapping("/register")
public class RegistrationController {

    // @InitBinder: configura el enlace del modelo de las acciones de este controlador.
    // StringTrimmerEditor(true): a cada cadena recibida se le quitan los espacios
    // sobrantes, y una cadena vacía se convierte en null
    @InitBinder
    public void initBinder(WebDataBinder binder) {

    }

    // ?html5=true: dejamos que el navegador valide el formulario antes de enviarlo
    @GetMapping("")
    public String display(@RequestParam(defaultValue = "false") boolean html5, Model model) {
        model.addAttribute("registration", new RegistrationModel());
        model.addAttribute("html5", html5);
        return "registration/registration";
    }

    // @ModelAttribute("registration"): el nombre del objeto en el modelo de la vista
    @PostMapping("")
    public String register(@Valid @ModelAttribute("registration") RegistrationModel input, BindingResult result,
            @RequestParam(defaultValue = "false") boolean html5, Model model) {
        if (result.hasErrors()) {
            // mostramos el formulario DE NUEVO: valores escritos (excepto las contraseñas),
            // y un mensaje bajo cada campo inválido (vea fragments/field.html)
            input.setPassword(null);
            input.setConfirmation(null);
            model.addAttribute("html5", html5);
            model.addAttribute("error", "The form contains errors.");
            return "registration/registration";
        }
        return "registration/welcome";
    }
}

    • Línea 5: el fragmento [field] se declara sin firma, es decir, sin lista de parámetros.     4.7.2. Validación del navegador

    Los atributos [required], [maxlength], [min], [max], [type="email"]... indican al navegador que valide el formulario antes de enviarlo: se notifica de inmediato al usuario mediante un tooltip, sin ninguna comunicación de ida y vuelta con el servidor. Este es el comportamiento que se obtiene al hacer clic en el enlace “enable it” (http://localhost:5000/register?html5=true), que elimina el atributo [novalidate] del formulario.

    Esta validación es una comodidad, no una medida de seguridad: se puede eludir simplemente eliminando el atributo [required] con las herramientas para desarrolladores del navegador, o enviando la solicitud con [curl]. La validación en el servidor sigue siendo esencial. Por eso el ejemplo desactiva la validación del navegador de forma predeterminada: para demostrar cómo funciona el servidor. El caso de estudio, en cambio, conserva ambas: los atributos HTML5 por comodidad y la validación en el servidor por seguridad.

    4.8. Ejemplo 20: El patrón Post/Redirect/Get

    Cuando un formulario POST se envía con éxito, la acción puede mostrar una página directamente. El problema surge si el usuario actualiza esa página (tecla F5): el navegador reenvía el formulario y la operación se realiza por segunda vez (un pedido realizado dos veces, una cita programada dos veces...). El patrón Post / Redirect / Get (PRG) evita este problema: una acción POST exitosa no genera una página; en su lugar, redirige a una página GET. Volver a cargar esta página simplemente activa otro GET, sin ningún efecto.

    Queda un detalle: la página GET debe mostrar un mensaje (“la tarea se ha agregado”), aunque este mensaje lo haya generado la acción POST en una solicitud distinta. [Spring MVC] proporciona los atributos flash para este fin: atributos definidos antes de la redirección, que persisten hasta la siguiente solicitud, donde se agregan a la plantilla y luego desaparecen. Esto se conoce como un mensaje flash. De forma predeterminada, [Spring MVC] almacena los atributos flash en la sesión HTTP del usuario: un espacio de memoria que el servidor asocia con cada navegador (el capítulo “Ámbitos de datos” está dedicado a este tema).

    package example21.services;

import java.util.ArrayList;
import java.util.List;
import java.util.Optional;

import org.springframework.stereotype.Service;

// los contactos, en memoria, compartidos por todos (singleton)
@Service
public class ContactsService {

    // un contacto: un identificador, un nombre, un número de teléfono
    public record Contact(int id, String name, String phone) {
    }

    private final List<Contact> contacts = new ArrayList<>(List.of(
            new Contact(1, "Marie Durand", "01 23 45 67 89"),
            new Contact(2, "Paul Martin", "06 12 34 56 78"),
            new Contact(3, "Philippe Jandot", "02 98 76 54 32")));
    private int lastId = 3;

    // synchronized: una sola solicitud a la vez ejecuta el método
    public synchronized List<Contact> list() {
        return List.copyOf(contacts);
    }

    // Optional: un contacto, o "nada" si no existe
    public synchronized Optional<Contact> read(int id) {
        return contacts.stream().filter(c -> c.id() == id).findFirst();
    }

    public synchronized Optional<Contact> edit(int id, String name, String phone) {
        for (int i = 0; i < contacts.size(); i++) {
            if (contacts.get(i).id() == id) {
                // un record es inmutable: lo reemplazamos por uno nuevo
                Contact edited = new Contact(id, name, phone);
                contacts.set(i, edited);
                return Optional.of(edited);
            }
        }
        return Optional.empty();
    }

    public synchronized Contact add(String name, String phone) {
        Contact contact = new Contact(++lastId, name, phone);
        contacts.add(contact);
        return contact;
    }

    public synchronized Optional<Contact> delete(int id) {
        Optional<Contact> contact = read(id);
        contact.ifPresent(contacts::remove);
        return contact;
    }
}

    @PostMapping("/{id:\\d+}/delete")
    public String delete(@PathVariable int id, RedirectAttributes redirect) {
        Contact contact = contacts.delete(id).orElseThrow(ContactsController::notFound);
        redirect.addFlashAttribute("flash", "The contact [" + contact.name() + "] has been deleted.");
        return "redirect:/contacts";
    }

    // una excepción que produce una respuesta 404
    private static ResponseStatusException notFound() {
        return new ResponseStatusException(HttpStatus.NOT_FOUND, "unknown contact");
    }
}

    Comentemos este código:

    • líneas 28–38: las dos páginas: la lista y el perfil del contacto. La restricción [{id:\\d+}] (vea el Ejemplo 02) solo acepta un identificador formado por dígitos;
    • línea 36: [orElseThrow] devuelve el contacto contenido en [Optional] o, si está vacío, lanza la excepción generada por la función que se le pasa: aquí, la referencia a método [ContactsController::notFound];
    • líneas 41–47: guardado de un registro con PRG. Los parámetros [name] and [phone] son obligatorios: [@RequestParam] no se puede usar sin [required = false];
    • líneas 50–56: duplicación, activada por un segundo botón del mismo formulario (atributo [formaction]);
    • líneas 58–63: eliminación, mediante un POST;
    • líneas 66–68: una excepción [ResponseStatusException] lleva un código HTTP y un motivo. Cuando la lanza una acción, genera una respuesta de error con ese código: en este caso, 404. Un contacto inexistente provoca así un 404 en las acciones [details], [save] y [delete]; en cambio, la duplicación no vuelve a leer el contacto: crea una copia a partir de los campos recibidos.

(() => {
  const modal = document.getElementById('confirmation-modal');
  const message = document.getElementById('confirmation-modal-message');
  let pending = null; // el formulario que se enviará si el usuario confirma

  // 1. interceptamos el envío de los formularios que requieren confirmación
  document.querySelectorAll('form[data-confirmation]').forEach((form) => {
    form.addEventListener('submit', (event) => {
      event.preventDefault(); // el envío se suspende
      pending = form;
      message.textContent = form.dataset.confirmation;
      modal.classList.remove('d-none'); // aparece la ventana
    });
  });

  // 2. los dos botones de la ventana
  modal.addEventListener('click', (event) => {
    const action = event.target.dataset.action;
    if (action === 'yes') {
      pending.submit(); // envío, SIN volver a disparar el evento 'submit'
    } else if (action === 'no') {
      modal.classList.add('d-none');
      pending = null;
    }
  });
})();
    • línea 3: el código está envuelto en una función que se ejecuta de inmediato, para evitar crear variables globales;
    • líneas 9–16: se intercepta el envío de cada formulario que tiene el atributo [data-confirmation]. [preventDefault()] suspende el envío; se guarda el formulario, la pregunta se coloca en la ventana ([textContent], no [innerHTML]: la pregunta se muestra como texto, nunca se interpreta como HTML) y se muestra la ventana;
