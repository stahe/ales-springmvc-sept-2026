    3. El modelo de la acción

    Una acción necesita la información enviada por el navegador: los parámetros de la URL ([?name=martin&age=42]), los campos de un formulario, el cuerpo JSON de la solicitud y, a veces, un encabezado HTTP de la solicitud. El curso original denomina al conjunto de esta información el modelo de la acción. Este capítulo muestra cómo [Spring MVC] proporciona esta información a la acción, la convierte al tipo correcto y la valida. Este proceso se llama enlace de datos ([data binding]).

    Nota sobre la terminología: en [Spring MVC], la palabra “modelo” ([Model]) designa principalmente los datos que una acción pasa a su vista (capítulo 4, “La vista y su modelo”). El modelo de una acción, tal como se usa en este capítulo, es lo que ella recibe.

    Los ejemplos 07 a 12 son, como los del capítulo anterior, módulos [Maven] de la carpeta [examples]. Puede ejecutar uno de ellos abriendo una terminal en esa carpeta y escribiendo [../mvnw spring-boot:run] ([..\mvnw spring-boot:run] en [Windows]); [Ctrl-C] detiene el servidor. Cada ejemplo tiene un archivo llamado [application.properties] que tiene este aspecto:

    package example07.controllers;

import java.util.Map;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;

@RestController
@RequestMapping("/parameters")
public class ParametersController {

    // /parameters/action01?name=martin: el parámetro de URL [name] -> el parámetro de acción [name]
    // required = false: el parámetro puede faltar, entonces vale null
    @GetMapping("/action01")
    public String action01(@RequestParam(required = false) String name) {
        return "name = [%s], of type %s".formatted(name, name == null ? "null" : name.getClass().getSimpleName());
    }

    // /parameters/action02?age=42: el valor se CONVIERTE al tipo del parámetro;
    // sin required = false, el parámetro es obligatorio
    @GetMapping("/action02")
    public String action02(@RequestParam int age) {
        return "age = [%d], of type int".formatted(age);
    }

    // /parameters/action03?age=42: Integer (y no int) acepta el valor null
    @GetMapping("/action03")
    public String action03(@RequestParam(required = false) Integer age) {
        return "age = [%s]".formatted(age);
    }

    // /parameters/action04?page=2: un valor por defecto si falta el parámetro
    @GetMapping("/action04")
    public String action04(@RequestParam(defaultValue = "1") int page) {
        return "page = [%d]".formatted(page);
    }

    // /parameters/action05?q=spring: el nombre del parámetro de URL, cuando difiere
    @GetMapping("/action05")
    public String action05(@RequestParam(name = "q", required = false) String search) {
        return "search = [%s]".formatted(search);
    }

    // /parameters/action06?name=martin&age=42: todos los parámetros a la vez
    @GetMapping("/action06")
    public Map<String, String> action06(@RequestParam Map<String, String> parameters) {
        return parameters;
    }
}

    Comentemos este código:

    • Líneas 16-17: la anotación [@RequestParam] asocia un parámetro de la acción con un parámetro de la URL (la parte que sigue a [?], conocida como cadena de consulta o [query string]). Salvo que se indique otra cosa, el parámetro de la URL tiene el mismo nombre que el parámetro de [Java]: [name]. Este nombre solo se conoce en tiempo de ejecución porque el proyecto padre de [Spring Boot] indica al compilador que lo conserve en el código compilado (opción [-parameters]). Una anotación puede aceptar argumentos con nombre, llamados atributos: [required = false] indica que el parámetro puede omitirse; en ese caso, equivale a [null]. Línea 18: el método [formatted] reemplaza cada aparición de [%s] en la cadena por el argumento siguiente; [name.getClass().getSimpleName()] es el nombre corto del tipo del valor;
    • Líneas 23-24: el parámetro se declara con el tipo [int]: [Spring MVC] convierte la cadena recibida (["42"]) en un número. Sin el atributo [required = false], [@RequestParam] hace que el parámetro sea obligatorio: este es el valor predeterminado de [required]. Un parámetro ausente, o cuya conversión falla, provoca un error 400, y la acción no se ejecuta;
    • líneas 29-30: un [int] no puede ser igual a [null]. Para un número opcional, el parámetro se declara con el tipo [Integer], la clase [Java], que "envuelve" un [int] ([wrapper]): un objeto [Integer] puede tener el valor [null], lo que permite distinguir entre "sin edad" y "edad 0";
    • líneas 35-36: el atributo [defaultValue] proporciona el valor que se usa cuando falta el parámetro (también hace que el parámetro sea opcional). Es una cadena, que se convierte de la misma manera que se convertiría el valor recibido;
    • líneas 41-42: el atributo [name] especifica el nombre del parámetro de la URL cuando difiere del del parámetro [Java]: el parámetro [search] de la acción recibe el parámetro [q] de la URL;
    • Líneas 47-48: un parámetro de tipo [Map<String, String>] anotado con [@RequestParam] recibe todos los parámetros de la URL, sin conversión: un diccionario (nombre del parámetro, valor). La acción lo devuelve tal cual, y [Spring MVC] lo serializa a JSON.

    • [message]: el mensaje de la excepción, incluido aquí porque las herramientas de desarrollo lo solicitaron;
    • [path]: la ruta de la solicitud.

    package example08.models;

import jakarta.validation.constraints.Email;
import jakarta.validation.constraints.Max;
import jakarta.validation.constraints.Min;
import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.NotNull;
import jakarta.validation.constraints.Pattern;
import jakarta.validation.constraints.Size;

// el modelo de la acción: una clase cuyos campos llevan todos sus restricciones
public class PersonModel {

    @NotBlank(message = "the name is required")
    @Size(min = 2, max = 20, message = "the name must have 2 to 20 characters")
    private String name;

    @NotNull(message = "the age is required")
    @Min(value = 0, message = "the age must be between 0 and 150")
    @Max(value = 150, message = "the age must be between 0 and 150")
    private Integer age;

    @NotNull(message = "the title is required")
    @Pattern(regexp = "Mr|Mme|Melle", message = "unknown title")
    private String title;

    // opcional: sin @NotNull
    @Email(message = "invalid email address")
    private String email;

    // los accesores (getters y setters): el enlace del modelo llena
    // cada campo mediante su setter; la serialización JSON lo lee mediante su getter
    public String getName() { return name; }
    public void setName(String name) { this.name = name; }

    public Integer getAge() { return age; }
    public void setAge(Integer age) { this.age = age; }

    public String getTitle() { return title; }
    public void setTitle(String title) { this.title = title; }

    public String getEmail() { return email; }
    public void setEmail(String email) { this.email = email; }
}

    Comentemos este código:

    • líneas 3-9: las anotaciones de validación, todas en el paquete [jakarta.validation.constraints];
    • líneas 14-16: el nombre es obligatorio y no puede estar vacío ([@NotBlank] rechaza [null], una cadena vacía y una cadena formada por espacios) y debe tener entre 2 y 20 caracteres ([@Size]). Cada anotación acepta un mensaje de error personalizado (atributo [message]);
    • líneas 18-21: la edad se convierte en un entero, es obligatoria ([@NotNull]) y debe estar entre 0 y 150 ([@Min], [@Max]). Se declara como [Integer] en lugar de [int], de modo que la "ausencia de edad" ([null]) sea detectada por [@NotNull] en lugar de asignarse como 0;
    • líneas 23-25: el título debe coincidir con la expresión regular [Mr|Mme|Melle] ([@Pattern]): debe ser uno de estos tres valores;
    • líneas 28-29: la dirección de correo electrónico es opcional (sin [@NotNull]); si está presente, debe ser válida ([@Email]). Todas las restricciones distintas de [@NotNull] y [@NotBlank] aceptan el valor [null]: eso es lo que hace opcional a un campo;
    • líneas 33-43: los accesores. Por convención, el valor del campo [name] se lee mediante el método [getName] ([getter]) y se escribe mediante el método [setName] ([setter]). Una clase que tiene un constructor sin parámetros (en este caso, el que proporciona implícitamente [Java]) y accesores que siguen esta convención se denomina JavaBean. Esta es la forma que espera el enlace de datos: [Spring MVC] crea el objeto mediante su constructor sin parámetros y luego, para cada parámetro de la solicitud, llama al setter del mismo nombre: [setName("martin")] para [?name=martin], después de convertir el valor al tipo del setter. El convertidor JSON, en cambio, lee los campos mediante sus getters.

    package example08.controllers;

import java.util.LinkedHashMap;
import java.util.Map;

import org.springframework.web.bind.annotation.GetMapping;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;

import example08.models.PersonModel;
import jakarta.validation.Valid;

@RestController
@RequestMapping("/persons")
public class PersonsController {

    // /persons/action01?name=martin&age=42&title=Mr
    // @Valid: el modelo se valida ANTES de que se ejecute la acción; si es
    // inválido, la solicitud se rechaza AUTOMÁTICAMENTE (error 400)
    @GetMapping("/action01")
    public Map<String, Object> action01(@Valid PersonModel person) {
        Map<String, Object> response = new LinkedHashMap<>();
        response.put("person", person);
        response.put("ageType", person.getAge().getClass().getSimpleName());
        return response;
    }
}

El parámetro es entonces un objeto de comando ([command object]), creado y poblado por el enlace de datos como se acaba de describir. Los parámetros de consulta que no corresponden a ningún setter se ignoran;

Si el enlace de datos o la validación fallan, [Spring MVC] lanza la excepción [MethodArgumentNotValidException]: la acción no se ejecuta y la respuesta es un error 400. Esto equivale al atributo [[ApiController]] de [ASP.NET Core MVC];
    • líneas 22-25: la acción devuelve la persona recibida y el tipo de su edad. [LinkedHashMap] es un diccionario que conserva el orden de inserción de sus claves: JSON las mostrará en ese orden.

    3.2.1. ¿Por qué una clase JavaBean y no un record?

@RequestMapping("/persons")

    // un parámetro BindingResult, justo después del modelo: la acción se ejecuta
    // SIEMPRE, y es la acción la que decide qué hacer con un modelo inválido
    @GetMapping(value = "/action01", produces = MediaType.TEXT_HTML_VALUE)
    public String action01(@Valid PersonModel person, BindingResult result) {
        // result: el resultado del enlace Y de la validación del modelo
        if (!result.hasErrors()) {
            return "<p>Welcome %s %s (%d years old)</p>".formatted(person.getTitle(), person.getName(), person.getAge());

        String items = result.getFieldErrors().stream()
                .map(error -> "<li>%s: %s</li>".formatted(error.getField(), error.getDefaultMessage()))
                .collect(Collectors.joining());
        return "<p>The form contains errors:</p><ul>" + items + "</ul>";
    }
}

    Analicemos este código:

    • Línea 20: el atributo [produces] de [@GetMapping] establece el tipo de la respuesta: [MediaType.TEXT_HTML_VALUE] es la constante ["text/html"]. Por lo tanto, la cadena devuelta por la acción se envía como una página HTML;
    • línea 21: la acción tiene un segundo parámetro, de tipo [BindingResult], colocado inmediatamente después de el modelo validado. Su presencia lo cambia todo: ante un error de enlace o de validación, [Spring MVC] ya no lanza una excepción; almacena los errores en este [BindingResult] y ejecuta la acción, que decide qué hacer con ellos. [BindingResult] cumple la misma función que [ModelState] en [ASP.NET Core MVC];
    • líneas 23-25: [hasErrors()] indica si hay errores. Si no los hay, se devuelve una página de bienvenida ([%d] se reemplaza por un entero);
    • líneas 27-29: de lo contrario, la lista de errores. [getFieldErrors()] devuelve la lista de errores asociados a un campo ([FieldError]), junto con el nombre del campo ([getField()]) y el mensaje ([getDefaultMessage()]). El procesamiento utiliza la API de [Java] streams ([Stream]): [stream()] genera los elementos de la lista uno por uno, [map] transforma cada uno (en este caso, un error en una línea: HTML [<li>]), [collect(Collectors.joining())] concatena todo en una cadena. El argumento de [map] es una lambda: una función anónima, escrita como [parameter -> expression];

    • línea 25: [@PostMapping] asocia la acción con las solicitudes POST, de la misma manera que [@GetMapping] lo hace con las solicitudes GET;
    • línea 26: [@RequestHeader("Content-Type")] proporciona el valor de un encabezado de la solicitud: en este caso, el tipo de su cuerpo;
    • línea 27: un parámetro de tipo [MultiValueMap<String, String>], anotado con [@RequestParam], recibe todos los parámetros de la solicitud. import java.time.LocalDate;
import java.time.format.DateTimeFormatter;
import java.time.format.DateTimeParseException;
import java.time.format.ResolverStyle;

import org.springframework.core.convert.converter.Converter;

// un conversor: convierte una fecha francesa "23/09/2026" en un LocalDate.
// Se usará para CUALQUIER parámetro de tipo LocalDate (vea WebConfig)
public class DateFrConverter implements Converter<String, LocalDate> {

    // uuuu: el año; STRICT: "31/02/2026" se rechaza (y no se convierte al 28 de febrero)
    private static final DateTimeFormatter FORMAT =
            DateTimeFormatter.ofPattern("dd/MM/uuuu").withResolverStyle(ResolverStyle.STRICT);

    @Override
    public LocalDate convert(String text) {
        try {
            return LocalDate.parse(text, FORMAT);
        } catch (DateTimeParseException e) {
            // fallo: una excepción, que Spring convierte en un error de conversión
            throw new IllegalArgumentException("[" + text + "] is not a valid dd/mm/yyyy date");
        }
    }
}
    • línea 12: un convertidor implementa la interfaz genérica [Converter<S, T>], donde [S] es el tipo de origen y [T] es el tipo de destino: aquí, de [String] a [LocalDate] (una fecha sin hora);
    • líneas 15-16: el formato de fecha, [dd/mm/yyyy]. En modo [STRICT], se rechaza una fecha que no existe (31/02/2026); este modo exige escribir el año como [uuuu] en lugar de [yyyy];
    • líneas 19-21: el único método de la interfaz, [convert], devuelve la fecha resultante;
    • líneas 22-25: si la conversión falla, el convertidor lanza una excepción.     package example12.binding;

import org.springframework.core.MethodParameter;
import org.springframework.web.bind.support.WebDataBinderFactory;
import org.springframework.web.context.request.NativeWebRequest;
import org.springframework.web.method.support.HandlerMethodArgumentResolver;
import org.springframework.web.method.support.ModelAndViewContainer;

// un "argument resolver": proporciona el valor de los parámetros anotados con @Language,
// leído del encabezado "Accept-Language: fr-FR,fr;q=0.9,en;q=0.8" -> "fr"
public class LanguageResolver implements HandlerMethodArgumentResolver {

    // ¿este resolver maneja este parámetro?
    @Override
    public boolean supportsParameter(MethodParameter parameter) {
        return parameter.hasParameterAnnotation(Language.class) && parameter.getParameterType() == String.class;
    }

    // el valor del parámetro
    @Override
    public Object resolveArgument(MethodParameter parameter, ModelAndViewContainer mavContainer,
            NativeWebRequest request, WebDataBinderFactory binderFactory) {
        String header = request.getHeader("Accept-Language");
        String first = header == null ? "" : header.split(",")[0].trim();
        return first.length() >= 2 ? first.substring(0, 2).toLowerCase() : "fr";
    }
}

    3.6.6. Conclusión

    El modelo de la acción se construye enlazando datos de la solicitud: parámetros de la URL y campos de formulario ([@RequestParam], objeto de comando), el cuerpo JSON ([@RequestBody]), encabezados ([@RequestHeader]) y todo lo que pueda proporcionar un resolutor personalizado. Los valores se convierten al tipo del parámetro y luego se validan según las restricciones de [Bean Validation] cuando el modelo está anotado con [@Valid]. Un error de conversión con un [@RequestParam], o un modelo no válido sin un [BindingResult], produce un error 400 sin ejecutar la acción: esto es adecuado para un servidor JSON. Para una aplicación HTML, el formulario es un JavaBean anotado con [@Valid], seguido de un parámetro [BindingResult] que la acción consulta (ejemplo 09), para poder volver a mostrar el formulario con sus errores.
